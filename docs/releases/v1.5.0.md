Review Markdown pull requests without leaving the rendered view: comment, suggest new wording, reply, resolve, edit, and jump between changes, in a comment box that works like GitHub's own. This is the first store update since 1.0.0, so it includes everything from 1.1 to 1.5.

**Install or update:** [Chrome Web Store](https://chromewebstore.google.com/detail/markdown-diff-cat-for-git/kabekbbeoajhpbcppidepmcbbjjochlj)

## New

### Comment in the rendered view (signed in to GitHub)

- Hover over a block and click **+**, or drag from **+** to another block to comment on a range. The comment lands on the right source line as an ordinary GitHub review comment: add a single comment, or start or add to your review
- Existing review threads show under the block they refer to, where you can reply, resolve, and unresolve them. Comments on the whole file show at the top of the file
- Edit or delete your own comments in place (delete asks for a second click), and preview a comment the way GitHub will show it
- Threads made outdated by a later commit stay out of the rendered view, like on GitHub

### A comment box that works like GitHub's

- Your avatar and "Add a comment on line R13" (`L` for the removed side), Write and Preview tabs, and the formatting toolbar in GitHub's order, with ⌘/Ctrl+B, I, E, K. ⌘/Ctrl+Z undoes a formatting step
- **Add a suggestion**, first in the toolbar as on GitHub, puts the lines you comment on into a ```` ```suggestion ```` block, so the author can apply your wording in one click. Reply boxes have the same toolbar
- **Comment** and **Start a review** stay off until you type
- The extension's text is in English, whatever language Chrome uses, to match GitHub's pages. A Korean setting is planned

### Jump between changes

- The top of each rendered file says how many places changed and how many review threads it has, with how many are open
- `]` and `[` go to the next or previous change on the page, `}` and `{` to the next or previous thread. The keys do nothing while you type

## Fixed

- A file GitHub cannot render goes back to the source view after 15 seconds instead of staying blank ([#22](https://github.com/drum-grammer/GITHUB-MD-DIFF/issues/22))
- No false `!` for files GitHub has not loaded yet, or shows only behind **Load Diff**
- When an edit does not change how the page looks (Markdown syntax, a link URL), the file says so and offers the source diff
- More blocks get **+**: HTML tables and paragraphs, GitHub alerts, and footnotes, including footnotes defined mid-document
- Faster on large pull requests: in one with 334 Markdown files, the extension's CPU time dropped from 1,182 ms to about 220 ms

Details for each step: [1.1.1 notes](v1.1.1.md), [1.3.0 testing](../reports/v1.3.0-testing.md), [1.4.0 testing](../reports/v1.4.0-testing.md).

## Permissions and privacy

Same permissions as 1.0.0: `storage` for the on/off setting, and it runs only on `https://github.com/*`. When you are signed in, the extension talks to GitHub, and only to GitHub, with the session you already have: it loads review threads and the Markdown files on the page, and posts the comments you write. Nothing goes to the developer or anyone else, no token is used, and there is no remote code. [Privacy policy](https://github.com/drum-grammer/GITHUB-MD-DIFF/blob/main/PRIVACY.md).

## How it was tested

- `pnpm verify release` on `4ba51b3`: 308 unit and DOM tests, typecheck, build, read-only canary against live GitHub (7/7), performance with the extension off and on (vscode-docs#10431: 222 ms extension CPU, folding in the same frame as GitHub's render), and the package
- Release scenarios on a public test repository ([drum-grammer/markdown-diff-cat-testbed](https://github.com/drum-grammer/markdown-diff-cat-testbed), `pnpm testbed`) in 5 GitHub diff layouts: 60/60 passed — real comments (single, range, removed line, reply, renamed file, table row, ⌘Enter, pending-review reply), suggestions from the comment and reply boxes, edit, delete, and preview, resolve and unresolve, seeded threads in place (whole-file, outdated, suggestion, formatted), a 2,400-line diff, and a 120-file pull request
- Re-exploration of 16 public pull requests (read-only): no extension errors, 99.8% of rendered blocks matched to their source lines
- End-to-end tests in Chromium with real pending comments: 12/12 in `pnpm release check`. In the `verify release` run one test timed out waiting for GitHub to show a just-posted pending comment; it passed on the next three runs

## 한국어

1.0.0 다음 첫 스토어 업데이트라 1.1부터 1.5까지가 모두 들어 있어요.

- **렌더링 보기에서 바로 코멘트**(GitHub 로그인): **+**를 누르거나 끌어서 범위에 달아요. 맞는 원문 줄에 붙는 보통의 리뷰 코멘트예요. 기존 스레드는 그 블록 아래에서 답글·해결하고, 파일 전체 코멘트는 파일 맨 위에 보여요. 내 코멘트는 그 자리에서 고치거나 지우고, 미리 볼 수 있어요
- **GitHub와 같은 코멘트 상자**: 아바타·"Add a comment on line R13"·쓰기/미리보기 탭·같은 순서의 서식 도구 막대와 단축키. 맨 앞의 **Add a suggestion**은 원래 줄을 제안 블록에 넣어, 작성자가 한 번에 반영하게 해요. 답글 상자에도 있어요. 확장 문구는 GitHub 화면에 맞춰 영어예요(한국어 설정은 예정)
- **바뀐 곳 사이 이동**: 파일 맨 위에 바뀐 곳·스레드 수, `]` `[`로 바뀐 곳, `}` `{`로 스레드 사이를 옮겨요
- **고친 것**: 렌더링이 안 되는 큰 파일(#22), 오탐 `!`, 화면에 드러나지 않는 수정 안내, HTML 표·알림·각주의 **+**, 큰 PR 속도(확장 CPU 1,182ms → 약 220ms)
- **권한은 1.0.0과 같아요**. 로그인한 경우 이미 있는 세션으로 GitHub하고만 통신해요

검증: `pnpm verify release`(단위 308 · 카나리 7/7 · 성능 · 패키지) · 테스트 저장소 시나리오 60/60(화면 모양 5가지, 실제로 코멘트·제안·답글·해결·편집·삭제) · 공개 PR 16개 재탐험(확장 오류 0, 원문 줄 연결 99.8%) · E2E 12/12(`release check`. `verify release`에서 GitHub가 방금 올린 보류 코멘트를 늦게 보여 준 한 건이 시간 초과였고, 다음 세 번은 모두 통과).

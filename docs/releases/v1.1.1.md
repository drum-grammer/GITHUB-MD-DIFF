Comment right in the rendered view, plus fixes and speed-ups from testing on 300 public pull requests and a dedicated test repository. 1.1.0 was never published, so this is the first update after 1.0.0.

**Install or update:** [Chrome Web Store](https://chromewebstore.google.com/detail/markdown-diff-cat-for-git/kabekbbeoajhpbcppidepmcbbjjochlj)

## New: comment in the rendered view (signed in to GitHub)

- Hover over a block and click **+**, or drag from **+** to another block to comment on a range. The comment lands on the right source line as an ordinary GitHub review comment: add a single comment, or start or add to your review
- While the comment box is open, the selected range keeps GitHub's yellow selection highlight
- Existing review threads show under the block they refer to, where you can reply, resolve, and unresolve them
- Files that already have inline review comments now open in the rendered view when you are signed in
- If GitHub changes the internal requests commenting relies on, commenting turns itself off while folding and tables keep working. The toolbar shows `!`, and a note in the corner links to a prefilled issue

## Fixed

- A file GitHub cannot render (its rendered view times out on some large files) goes back to the source view after 15 seconds instead of staying blank, and is not reported as a problem ([#22](https://github.com/drum-grammer/GITHUB-MD-DIFF/issues/22))
- No false `!` for files GitHub has not loaded yet in large pull requests, or that it shows only behind **Load Diff**
- Files renamed without changes stay in the source view. Renamed files with changes get **+** and their review threads
- When an edit does not change what the page looks like (Markdown syntax, a link URL, an escaped character), the file says so at the top, with a **Show source diff** button
- A review thread inside a large unchanged section no longer unfolds the whole section
- More blocks get **+**: HTML tables and paragraphs, GitHub alerts (`[!NOTE]`), and footnotes, including footnotes defined in the middle of a document (GitHub shows them at the end) — 99.7% of rendered blocks matched their source lines across the test set

## Faster on large pull requests

- Rendered views are requested at most 10 at a time, starting with the files on screen
- Files whose state is settled are not checked again. In a pull request with 334 Markdown files, the extension's own CPU time over 25 seconds dropped from 1,182 ms to 220 ms, and folding still lands in the same frame as GitHub's rendered diff

## Permissions and privacy

Same permissions as 1.0.0: `storage` for the on/off setting, and it runs only on `https://github.com/*`. New in this release: when you are signed in, the extension talks to GitHub, and only to GitHub, with the session you already have. It loads the pull request's review threads and the Markdown files it shows, and posts the comments you write. Nothing goes to the developer or anyone else, no token is used, and there is no remote code. See the updated [privacy policy](https://github.com/drum-grammer/GITHUB-MD-DIFF/blob/main/PRIVACY.md).

## How it was tested

- 209 unit and DOM tests, 11 end-to-end tests in Chromium (including posting comments to a demo pull request as a pending review and checking their lines), and a weekly read-only canary against live GitHub (7/7)
- Read-only exploration of 300 Markdown pull requests in 128 public repositories, three rounds (`pnpm explore`): false alerts 3 → 0, matched blocks 98.4% → 99.7%
- Performance on 8 public pull requests with the extension off and on (`pnpm perf`)
- Release scenarios on a public test repository ([drum-grammer/markdown-diff-cat-testbed](https://github.com/drum-grammer/markdown-diff-cat-testbed), `pnpm testbed`): 14/14 passed. They post real comments (single line, range, removed line, reply, renamed file), resolve and unresolve threads, check that seeded threads land in place, and open a 2,400-line diff and a 120-file pull request. Each comment is read back through the GitHub API to check its path, side, and line. The first run found the mid-document footnote bug above. [Report](https://github.com/drum-grammer/GITHUB-MD-DIFF/blob/main/docs/reports/v1.1.1-testbed.md)

## 한국어

1.0.0 다음 첫 업데이트예요(1.1.0은 게시되지 않았어요).

- **렌더링 보기에서 바로 코멘트**(GitHub 로그인): 블록에 마우스를 올려 **+**를 누르거나, **+**에서 끌어 범위에 달아요. 코멘트는 맞는 원문 줄에 붙는 보통의 리뷰 코멘트예요. 상자가 열려 있는 동안 고른 범위에 GitHub와 같은 노란 음영이 남아요. 기존 스레드는 그 블록 아래에서 답글·해결할 수 있어요
- **고친 것**
  - GitHub가 렌더링을 만들지 못한 큰 파일은 15초 뒤 원문 보기로 돌아가고 `!`를 띄우지 않아요(#22)
  - 큰 PR의 아직 안 채워진 파일, "Load Diff" 파일에서 생기던 오탐 `!`를 없앴어요
  - 이름만 바뀐 파일은 원문 그대로 두고, 이름이 바뀌고 내용도 바뀐 파일에도 **+**와 스레드가 붙어요
  - 렌더링에 드러나지 않는 변경은 안내와 "원문 보기로" 버튼으로 알려요
  - 스레드가 있는 큰 "변경 없음" 구간도 접혀요
  - HTML 표·알림(`[!NOTE]`)·각주에도 **+**가 붙어요. 문서 중간에 쓴 각주도 돼요(연결 99.7%)
- **빨라졌어요**: md 334개 PR에서 확장 CPU 1,182ms → 220ms(25초 기준)
- **권한은 1.0.0과 같아요**. 로그인한 경우 이미 있는 세션으로 GitHub하고만 통신해요(스레드·원문 읽기, 내가 쓴 코멘트 올리기)

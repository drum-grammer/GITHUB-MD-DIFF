Large Markdown files that GitHub cannot render now get a rendered diff anyway: the extension draws it in your browser. If that fails too, you get the source diff and the reason instead of an error line.

**Install or update:** [Chrome Web Store](https://chromewebstore.google.com/detail/markdown-diff-cat-for-git/kabekbbeoajhpbcppidepmcbbjjochlj)

## New: rendered in your browser when GitHub cannot (signed in to GitHub)

- On some large Markdown files GitHub's server gives up on the rendered view: after about 10 seconds it answers 504 and the page shows only “This rich diff is not supported at the moment.” Size alone does not decide it. A 437 KB and a 224 KB design document failed every time, while a 261 KB document in the same pull request rendered in 2 seconds
- The extension now reads the old and new text of that file and draws the rendered diff in your browser. It uses the same engine as local review and puts the result where GitHub's rendered diff would be
- Folding, table merging, jumping between changes and comments (**+**) work as usual. Math is drawn by GitHub's own page
- On those two documents, the rendered diff appeared 1 to 2 seconds after GitHub's 504
- A note above the file says it was rendered in your browser and may differ slightly from GitHub's rendering, with **Show source diff**
- Only files near the screen are rendered, one at a time, up to about 600,000 characters per side
- Design and measurements: [docs/local-render](https://github.com/drum-grammer/GITHUB-MD-DIFF/blob/main/docs/local-render/README.md)

## Fixed

- **When GitHub cannot render a file and the browser cannot either, you now get the source diff and the reason.** Before, you saw GitHub's error line, then a collapsed **Load Diff**. This happens when the file's text cannot be loaded, or the file is over the size limit
- **No more 15-second wait.** The extension switches to the source view as soon as GitHub shows its error. It loads the source diff even when GitHub hid it behind **Load Diff**, and says why in one line
- **Try rich diff again** is your choice. If GitHub fails again, the extension does not switch that file back

## Also in this release

- The local review command-line tool `markdown-diff-cat` shares this version number. It shows the same rendered Markdown diff for your working tree in a local page, and hands block comments to coding agents (Codex annotation attributes). See [packages/review](https://github.com/drum-grammer/GITHUB-MD-DIFF/blob/main/packages/review/README.md). Its npm release is announced separately
- Under the hood, without visible change:
  - markdown-it 15
  - shared modules split out so the extension and local review use the same rendering-diff code

## Permissions and privacy

The permissions are the same as 1.5.1: `storage` for the on/off setting, and the extension runs only on `https://github.com/*`.

Rendering in the browser reads the Markdown file's text from GitHub with the session you already have. These are the same requests comments already use. Nothing goes to the developer or anyone else, no token is used, and there is no remote code.

  - Canary against live GitHub: 9 of 9
  - Local review: 198 unit and integration tests, and 15 end-to-end tests

  - Edit, delete and preview, resolve and unresolve
  - Seeded threads in place: whole-file, outdated, suggestion and formatted
  - A 2,400-line diff and a 120-file pull request

- Performance with the extension off and on: extension CPU 106 ms (ko.react.dev#1565) and 301 ms (vscode-docs#10431, 334 Markdown files), about the same as the build before rendering in the browser was added (within run-to-run noise). Folding lands in the same frame as the rendered diff
- The two documents that started this work (in a private repository): with no faked responses, both rendered 1 to 2 seconds after GitHub's 504. The note stayed through scrolling and a theme change

## 한국어

GitHub가 렌더링하지 못한 큰 마크다운 파일도 이제 렌더링 diff로 봐요.

- **GitHub가 못 그리면 브라우저에서 그려요**(GitHub 로그인)
  - 큰 파일에서 GitHub 서버가 10초쯤 렌더링하다 504로 끊으면, 화면에는 "This rich diff is not supported at the moment."만 남아요
  - 이제는 확장이 옛·새 원문을 받아 브라우저 안에서 렌더링 diff를 그려, GitHub 렌더링이 있을 자리에 넣어요. 엔진은 로컬 리뷰와 같아요
  - 접기·표 합치기·변경 사이 이동·코멘트(**+**)가 평소대로 돌아요. 수식은 GitHub 페이지가 그려요
  - 파일 위 안내 한 줄이 "브라우저에서 그렸다"고 알려 주고, **Show source diff** 버튼이 있어요
  - 계기가 된 437 KB·224 KB 문서에서 GitHub 504 뒤 1~2초 안에 그려졌어요
- **고친 것**
  - 브라우저에서도 못 그리면, GitHub 오류 한 줄과 접힌 **Load Diff** 대신 원문 diff를 펼치고 까닭을 한 줄로 알려요
  - 실패 안내를 보자마자 바꿔요. 예전에는 15초를 기다렸어요
  - **Try rich diff again**은 사람의 선택이라, 또 실패해도 되돌리지 않아요
- **함께**: 로컬 리뷰 명령줄 도구 `markdown-diff-cat`이 같은 번호를 써요. npm 배포는 따로 알려요
- **권한은 1.5.1과 같아요**. 원문은 코멘트가 이미 쓰는 요청으로, 있는 로그인 세션으로 GitHub에서만 읽어요

The local review command-line tool `markdown-diff-cat` can now review a GitHub pull request: the same rendered Markdown diff page, existing review threads under their blocks, and your comments added to your pending review only when you confirm. The Chrome extension does not change in this version, so the Chrome Web Store stays on 1.6.0.

**Install or update:** `npx -y markdown-diff-cat@1.7.0 review --pr <number>` ([npm](https://www.npmjs.com/package/markdown-diff-cat)) · the extension: [Chrome Web Store](https://chromewebstore.google.com/detail/markdown-diff-cat-for-git/kabekbbeoajhpbcppidepmcbbjjochlj) (1.6.0, unchanged)

## New: pull request mode in `markdown-diff-cat` (needs the GitHub CLI `gh`, signed in)

- `markdown-diff-cat review --pr <number|URL>`, run in a clone of the repository, shows the pull request's Markdown changes in the local review page. It fetches the pull request into `refs/markdown-diff-cat/pr/<number>/` without touching your branches or working tree, and compares from the merge base the way GitHub's "Files changed" does. In a fork it fetches from the remote that points at the base repository
- Existing review threads appear under their blocks; whole-file threads at the top of the file; outdated ones are counted and left on GitHub. You can reply
- Your comments stay drafts in the page. **Add to pending review** opens a confirm dialog with the pull request, the count and each comment, and shows where each one will go. Only after you press **Add** do they go to **your pending review** (an existing one is reused). Nothing is published from the page: you submit the review on GitHub
- GitHub accepts line comments only inside the pull request's diff. A comment that reaches outside it is trimmed to the changed lines; one on unchanged lines becomes a whole-file comment with the quoted lines. A suggestion whose lines moved becomes plain text so it cannot apply to the wrong lines
- If new commits arrive after you opened the page, nothing is added. **Redraw** fetches the pull request again; a comment whose lines changed is not added at its old line numbers
- **Send to agent** works here too, for fixing your own pull request: your comments plus the threads by others that you tick. The handoff names the base and head commits and warns when your working tree is not on the pull request head
- `stop --clean` also removes the fetched refs

## Fixed

Nothing — the extension is the same as 1.6.0.

## Permissions and privacy

The extension's permissions are unchanged (`storage`, `https://github.com/*`).

Pull request mode reaches GitHub only through the GitHub CLI (`gh`), which keeps your credentials; `markdown-diff-cat` never reads a token. Comment text goes to `gh` as JSON on standard input, never as a command-line argument. Nothing is published without you: the page adds only to your pending review. Worktree mode still sends nothing anywhere.

## 한국어

로컬 리뷰 명령줄 도구 `markdown-diff-cat`으로 이제 GitHub PR도 리뷰해요. 크롬 확장은 1.6.0과 같아서 스토어는 1.6.0 그대로예요.

- **PR 모드** — `markdown-diff-cat review --pr <번호|URL>`(저장소 clone 안에서, GitHub CLI `gh` 로그인 필요)
  - PR을 `refs/markdown-diff-cat/pr/<번호>/`로 받아 같은 리뷰 페이지에 그려요. 내 브랜치·작업 트리는 그대로예요. 포크면 base 저장소 원격에서 받아요
  - 기존 리뷰 스레드가 블록 아래에, 파일 전체 스레드는 파일 위에 보이고 답글을 달 수 있어요. 낡은 스레드는 수만 보여요
  - 코멘트는 페이지에 초안으로 있다가 **Add to pending review** → 확인 상자(PR·건수·글, 초안마다 어디에 들어가는지) → **Add**를 눌러야 **내 보류 중 리뷰**에만 들어가요. 제출은 GitHub에서 직접 해요
  - diff 밖으로 나간 범위는 바뀐 줄로 자르고, 바뀌지 않은 줄의 코멘트는 인용을 붙인 파일 전체 코멘트가 돼요
  - 새 커밋이 오면 아무것도 넣지 않아요. **Redraw**로 다시 받고, 줄이 바뀐 코멘트는 옛 줄 번호로 넣지 않아요
  - **Send to agent**도 돼요 — 내 코멘트와 내가 고른 남의 스레드
- **권한**: 확장은 그대로예요. PR 모드는 `gh`를 통해서만 GitHub에 가고, 토큰을 읽지 않아요

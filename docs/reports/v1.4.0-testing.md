# Markdown Diff Cat 1.4.0 테스트 보고서 — GitHub 상자 모양의 코멘트 상자

> 2026-10-10 · 테스트 저장소 [drum-grammer/markdown-diff-cat-testbed](https://github.com/drum-grammer/markdown-diff-cat-testbed)(내용 v2) · 앞선 보고서: [1.3.0](v1.3.0-testing.md) · 아직 게시하지 않은 변경: [UNRELEASED](../releases/UNRELEASED.md)
>
> **English summary** — The comment box in the rendered view looked different from GitHub's own: a small grey "Line 37" label, pill tabs, no formatting toolbar, and a green "Start a review" even with nothing typed. 1.4.0 rebuilds it from GitHub's actual box, measured in the live page (structure, colors, sizes): your avatar and a bold "Add a comment on line R13" (`L` on the removed side), Write / Preview tabs on a bordered header, GitHub's formatting toolbar with the same icons and order, and **Comment** / **Start a review** off until you type. A code review before merging found seven issues in the first version (formatting edge cases, Ctrl+B/E/K taken from macOS text editing, shortcuts firing during Hangul composition, toolbar keyboard focus), all fixed with tests. `pnpm verify release` passes 10/10 on the final commit. Extension CPU on large pull requests is the same as 1.3.0 within run-to-run noise.

## 4. 성능 — 1.3.0과 나란히

같은 기기(맥 미니)·같은 시간대, 확장 끔·켬을 번갈아 여는 `pnpm perf`(3회씩). 버전도 묶음마다 번갈아 돌렸다. 숫자는 확장 CPU(ms), 저장된 9회를 모은 것.

| PR | 1.3.0 | 1.4.0 |
|---|---|---|
| microsoft/vscode-docs#10431(md 334개) | 214–281, **중앙 245** | 209–276, **중앙 244** |
| reactjs/ko.react.dev#1565(md 56개) | 86–129, **중앙 115** | 89–152, **중앙 123** |

묶음 하나만 보면 어느 쪽이든 40ms까지 앞서거니 뒤서거니 했다(예: vscode-docs 첫 묶음 중앙 210 vs 251, 둘째 254 vs 243, 셋째 237 vs 250). 같은 버전 안의 흔들림이 그만큼이라, 차이는 그 안이다. CPU 프로파일의 많이 쓴 함수 목록에 새 코드(`formLabel`·`toolbar`·`formatEdit` 등)는 한 번도 나오지 않았다 — 새 코드는 "+"를 눌러 상자를 열 때만 돌고, 훑기·접기 경로에는 더하지 않았다. 렌더링→접기는 모두 0ms. 번들(content.js)은 360,525 → 371,968바이트(+11KB, 아이콘 경로 10개·서식 함수).

## 5. 관리자가 써 본 뒤 더한 것(2026-10-11)

- **목록 버튼이 쌓이던 것**: 글머리 → 번호 → 할 일을 차례로 누르면 `- 1. - [ ]`이 됐다. 목록 버튼이 자기 표시만 떼었기 때문이다. 이제 목록 종류를 바꾸면 앞머리를 갈아 끼운다(`3e2c9b6`, 단위 테스트 1개)
- **제안(suggestion) 버튼**: GitHub 상자처럼 도구 막대 맨 앞(± 아이콘). 누르면 코멘트하는 오른쪽 줄의 원문(머리 커밋)을 ```` ```suggestion ```` 블록으로 넣고 커서를 그 끝에 둔다. 원문에 백틱 펜스가 있으면 더 긴 펜스로 감싼다. 지운 쪽(L) 줄에는 버튼이 없다(GitHub와 같다). 단위 테스트 4개, 테스트 저장소 T05가 표 행·HTML 표·목록·알림·코드 블록(3줄)·각주에서 들어간 글이 원문과 같은지, 지운 쪽 각주에는 버튼이 없는지 확인한다
- 언어: 확장 문구는 크롬 화면 언어를 따른다(한국어면 한국어, 그 밖은 영어). GitHub 화면은 영어만 있어 크롬이 한국어면 상자 문구가 GitHub와 다르게 보인다 — 의도한 것

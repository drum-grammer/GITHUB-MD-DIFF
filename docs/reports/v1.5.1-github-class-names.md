# Markdown Diff Cat 1.5.1 보고서 — GitHub 클래스 이름 형식 변경으로 1.5.0이 멈춘 일

> 2026-10-14 · 다음에 할 일의 정본: [runbook — GitHub 화면이 바뀌었을 때](../runbooks/github-ui-change.md) · 앞선 보고서: [1.4.0](v1.4.0-testing.md)
>
> **English summary** — 1.5.0 was published to the Chrome Web Store on 2026-10-14 and did nothing on the signed-in "Files changed" page. The package was identical to the one uploaded; GitHub had renamed the CSS module classes the extension used to find files (`Diff-module__diff__hash` → `diff__hash`, no `-module__` class left on the page) sometime after the last full verification on 2026-10-11. Proof: on the live page the store build added nothing; adding the old class names back by hand made the same build render, fold and navigate at once; the signed-in end-to-end tests (6) and the canary's three screen checks failed with "element not found", while the pull request data checks and the signed-out page passed. It was missed because the tests only see GitHub as it is on the day they run, the daily canary had never run, and the extension stayed silent when it found no files. 1.5.1 finds files by their anchor id and page structure first, accepts both class formats, warns when it cannot read any file, shares one set of selectors with every test and script, and the canary now fails on a class format change before users notice.

## 1. 확인한 것

- **패키지는 그대로다** — 설치된 스토어판 `1.5.0_0`의 `content.js`·`background.js`·`styles.css`가 GitHub Release v1.5.0의 zip(SHA-256 `c1077b8c…`)과 바이트까지 같다. 다른 것은 스토어 서명(`_metadata/`)과 JSON 줄바꿈뿐
- **화면이 바뀌었다** — 로그인 화면에 `-module__` 클래스가 0개. 파일 묶음은 `diffTargetable__jbrCub diff__GZFl4M`, 머리는 `diff-file-header__CV6GPS`. GitHub가 내려보내는 CSS(`pull-requests.<해시>.module.css`)도 `.d-contents__KzrRnz` 꼴뿐
- **그것이 원인이다** — 같은 탭에서 파일 묶음·머리·이름에 옛 형식 클래스를 손으로 덧붙이자, 설치된 스토어판이 곧바로 렌더링 보기로 바꾸고 변경 5곳 탐색·변경 없는 블록 접기까지 했다(확장 요소 0 → 9)
- **시험으로도** — 1.5.0 그대로 2026-10-14에 돌림

  | 시험 | 결과 |
  |---|---|
  | 단위 312 | 통과 — 저장해 둔 화면 사본(옛 형식)으로만 돈다 |
  | 로그아웃 E2E 3 | 통과 |
  | 로그인 E2E 7 | **6 실패**(1은 쓰기 모드 전용) — 모두 파일 묶음 `element(s) not found` |
  | canary 7 | **3 깨짐** — 화면 셋. PR 데이터·파일 원문·로그인·로그아웃 화면은 통과 |

## 2. 왜 놓쳤나

1. **시험은 그날의 GitHub만 본다** — 1.5.0 검증은 2026-10-11에 모두 통과했고, 제출(10-13) 뒤 심사 중에 GitHub가 바뀌었다. 시험에도 같은 옛 선택자가 9곳 박혀 있어서 돌렸다면 바로 깨졌겠지만, 그 사이 돌린 것이 없었다
2. **매일 점검(canary)이 돌지 않았다** — 상시 켠 맥에 예약은 설치했지만 그 맥의 화면 로그인이 없어 한 번도 실행되지 않았다. 점검이 멈춘 것을 알려 주는 장치도 없었다
3. **확장이 조용히 실패했다** — 경고(툴바 `!`·구석 안내)는 찾은 파일마다의 결과로만 만들었다. 파일을 하나도 못 찾으면 결과가 비어 "문제 없음"이 됐다
